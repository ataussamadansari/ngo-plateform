Implement the volunteer onboarding engine and screening queue, allowing prospective community members to apply online with skills and ID proof, and equipping administrators to inspect applicants and approve them with automated unique volunteer codes.

Purpose: Empowers the NGO to scale its community volunteer base securely and maintain an organized, verifiable volunteer roster.
Output: Volunteer request validation, code generation service, public application views, administrative review queue, and automated feature tests.
</objective>

<task type="auto">
  <name>Task 1: Form Validation Request & Sequential Code Generator Service</name>
  <files>app/Http/Requests/StoreVolunteerRequest.php, app/Services/VolunteerCodeService.php</files>
  <read_first>app/Models/Volunteer.php</read_first>
  <action>
    1. Create `app/Http/Requests/StoreVolunteerRequest.php`:
       - `full_name`: required, string, max:150
       - `email`: required, email, max:150, unique:volunteers,email
       - `phone`: required, string, max:20, unique:volunteers,phone
       - `city`: required, string, max:100
       - `address`: nullable, string, max:500
       - `occupation`: nullable, string, max:100
       - `skills`: required, array, min:1
       - `skills.*`: string, max:50
       - `availability`: required, in:weekdays,weekends,flexible
       - `profile_photo`: nullable, file, image, mimes:jpeg,png,webp, max:2048
       - `id_proof`: nullable, file, mimes:jpeg,png,webp,pdf, max:2048
    2. Create `app/Services/VolunteerCodeService.php`:
       - Method `generateNextCode(): string`:
         - Retrieves prefix: `$prefix = setting('volunteer_prefix', 'KSF');`
         - Retrieves current year: `$year = date('Y');`
         - Counts approved/coded volunteers for current year:
           `$count = Volunteer::whereNotNull('volunteer_code')->where('volunteer_code', 'like', "{$prefix}-VOL-{$year}-%")->count();`
         - Formats 4-digit sequence: `$sequence = str_pad($count + 1, 4, '0', STR_PAD_LEFT);`
         - Returns `"{$prefix}-VOL-{$year}-{$sequence}"` (e.g. `KSF-VOL-2026-0001`).
  </action>
  <verify>
    Run `php artisan tinker --execute="echo class_exists(\App\Services\VolunteerCodeService::class);"` - outputs true.
  </verify>
  <acceptance_criteria>
    - Form request validates contact uniqueness, skills array, and file size limits
    - VolunteerCodeService produces structured, collision-resistant sequential codes
  </acceptance_criteria>
  <done>Volunteer validation request and code generation service are created.</done>
</task>

<task type="auto">
  <name>Task 2: Public Volunteer Registration & Admin Screening Controllers</name>
  <files>app/Http/Controllers/VolunteerController.php, app/Http/Controllers/Admin/AdminVolunteerController.php, routes/web.php</files>
  <read_first>routes/web.php, app/Models/Volunteer.php</read_first>
  <action>
    1. Create `app/Http/Controllers/VolunteerController.php`:
       - `create()`:
         - Defines standard skill choices (Health & Medical Relief, Child Education & Tutoring, Food Distribution, Disaster Response, Event Coordination, Logistics, Media & Photography, Fundraising).
         - Returns `view('volunteers.create', compact('skills'))`.
       - `store(StoreVolunteerRequest $request)`:
         - Stores `profile_photo` in `storage/app/public/volunteers/photos` if present.
         - Stores `id_proof` in `storage/app/public/volunteers/id_proofs` if present.
         - Creates `Volunteer` record with `status = 'pending'`.
         - Redirects to `volunteers.success` with applicant name flashed.
       - `success()`:
         - Returns `view('volunteers.success')`.
    2. Create `app/Http/Controllers/Admin/AdminVolunteerController.php`:
       - `index(Request $request)`:
         - Filters by `status` (`pending`, `approved`, `rejected`, `inactive`, or `all`), `city`, and search (`full_name`, `email`, `phone`, `volunteer_code`).
         - Paginates 15 per page.
         - Aggregates metrics: Total Applicants, Pending Reviews, Approved Volunteers.
         - Returns `view('admin.volunteers.index', ...)`.
       - `show(Volunteer $volunteer)`:
         - Loads registrations with events: `$volunteer->load('eventRegistrations.event')`.
         - Returns `view('admin.volunteers.show', compact('volunteer'))`.
       - `approve(Volunteer $volunteer, VolunteerCodeService $codeService)`:
         - Runs in `DB::transaction()`: generates code if not already assigned, updates `status = 'approved'`, `joined_at = today()`.
         - Redirects with success flash message.
       - `reject(Volunteer $volunteer)`:
         - Updates `status = 'rejected'`.
         - Redirects with notice flash message.
    3. Register routes in `routes/web.php`:
       - Public:
         - `GET /volunteer-join` -> `VolunteerController@create` -> `volunteers.create`
         - `POST /volunteer-join` -> `VolunteerController@store` -> `volunteers.store` (throttle:5,1)
         - `GET /volunteer-join/success` -> `VolunteerController@success` -> `volunteers.success`
       - Admin:
         - `GET /admin/volunteers` -> `AdminVolunteerController@index` -> `admin.volunteers.index`
         - `GET /admin/volunteers/{volunteer}` -> `AdminVolunteerController@show` -> `admin.volunteers.show`
         - `POST /admin/volunteers/{volunteer}/approve` -> `AdminVolunteerController@approve` -> `admin.volunteers.approve`
         - `POST /admin/volunteers/{volunteer}/reject` -> `AdminVolunteerController@reject` -> `admin.volunteers.reject`
  </action>
  <verify>
    Run `php artisan route:list --name=volunteers` to verify all public and admin endpoints.
  </verify>
  <acceptance_criteria>
    - Public volunteer routes rate-limited
    - Admin approval assigns sequential code inside database transaction
  </acceptance_criteria>
  <done>Volunteer controllers and routes are registered.</done>
</task>
